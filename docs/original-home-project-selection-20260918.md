# 既存ホーム画面の維持とプロジェクト表示（2026-09-18）

## 方針

回答率は回答者の達成感・回答意欲を支える重要な情報として維持する。
検証用の別一覧画面を取り除き、Devも既存Main.storyboardのホーム画面へ接続する。
アイコン、円グラフ、達成度メッセージ、回答カード、履歴、サブメニュー、設問の配置を再利用する。
未回答のSurveyがあっても円グラフを表示し、スクロールで自動的に隠さない。
回答率の分母・分子は従来どおり取得済み全割当数・回答済み割当数。期限切れを分母から除外する等の変更はない。

## プロジェクト

ユーザー確認済みの方針：配布用はProto、開発用はDev。
ログイン画面に選択メニュー、ホーム上部に接続中の名前、サブメニューにプロジェクト切り替えを置く。
現段階では各アプリで利用可能なプロジェクトは1件のみ。現在のプロジェクトを選び直す操作はセッション・データを変更しない。
名前だけの架空の選択肢は追加しない。DevからProtoへ接続したり、Firebaseを動的に切り替えたりしない。
複数の研究プロジェクトを追加するときは、所属確認・API経路・セッションとローカルデータの分離を含めて拡張する。

## デザインと認証

コーラル（#FF5857）を基調にし、文字は読みやすい濃色を使用。
iOS 26以上ではメニューボタンとプロジェクト選択にLiquid Glass、透明度低減時・旧OSでは通常のボタンを使用。
設問のイラストも元のものを使用する。
DevのGoogle認証後は/api/meで解決した利用者IDを既存ホームに引き継ぎ、Googleメールのローカル部からIDを生成しない。
回答取得時は認証トークンを更新し、HTTP失敗・不正JSON・ログアウト後の応答を成功扱いしない。
Devではデバイストークン登録を行わない。Protoの既存ユーザー名・パスワード認証は維持。
追加文言は日本語・英語のLocalizable.stringsで管理する。

## 範囲

iOSアプリの変更。サーバー・Firebase設定・既存Surveyデータは変更しない。
Androidへの同等の画面反映と、複数プロジェクト間の実際のデータ切り替えは今回のiOS画面検証に含まない。

## 検証

- DevDebug / ProtoDebug の署名付きシミュレータービルド成功。
- Devを日本語で起動し、円グラフ（3件中3件・100%）、達成度メッセージ、元の回答一覧、接続中Dev表示を確認。
- サブメニューのプロジェクト選択にDevだけがチェック付きで表示されることを確認。
- ログアウト後のログイン画面で、認証ボタンとプロジェクト選択が同時に表示されることを確認。
- Protoログイン画面で、Proto選択・ユーザー名・パスワード・ログインボタンの配置を日本語で確認。Protoへのログインは行っていない。
- この変更では回答送信・既存データの編集は行っていない。
- 複数プロジェクトの切り替え試験は、利用可能プロジェクトが1件のため対象外。
